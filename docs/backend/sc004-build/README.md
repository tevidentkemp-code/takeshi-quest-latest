SC-004 real implementation package. Production activation and platform acceptance are recorded by the controller separately.

The live browser sends POST `{action, request_id, body}` to `sq-match-control`. Controller operations require `X-SQ-Match-Controller`; admin operations require the exact permanent Supabase Auth bearer JWT. The Edge verifies that JWT with `getUser`, then derives its user/session IDs. SQL checks the permanent confirmed user, live `auth.sessions` row and private allowlist on every admin operation. Request JSON cannot supply those identities or a service credential.

Creation returns a server-minted UUID and `sqmc1_` capability. A server-only 32-byte HMAC key derives the capability from action, random request UUID and canonical initiation body. Exact lost-response retries return the same authority; changed bodies conflict. SQL stores only a SHA-256 hash. Keep the issuance key across an operational rollback. A public match UUID, player name or old cached match cannot claim authority.

Gameplay API:

- `create_match`: `{mode, roster, target_wins, match_format, rules}`. Modes: official, practice, turbo, vs_shadow. `match_format` is series or single. Response includes match_id, canonical roster, mode, rules, expiry and capability. Guest Practice series retains match wins; single Practice/VsShadow permits one accepted game. VsShadow persists one real player under public Practice semantics.
- `reserve_game`: `{match_id, game_number}`. Returns minted game_id, number and pending/completed status. Pending slots are private; no public unfinished game triggers the broken historical finish-UPDATE high-score function.
- `reset_game`: `{match_id, game_id}`. Only unaccepted slots may reset; accepted history is immutable.
- `update_roster`: `{match_id, roster}`. Identity remains canonical; initials, avatar_id, nickname and display_name may change only within this controller snapshot. Pre-accept removal to one downgrades to Practice. Accepted games are never rewritten. Existing late-entry UI preserves the before-17s target and between-Game1/2 rules; no elapsed-seconds rule was invented.
- `complete_game`: `{match_id, game_id, state, totals, winner_indexes?}`. The existing canonical board and dart format remain; server validates scope, dimensions and aggregate consistency. Accepted game, proper high-score route and current match wins commit atomically. An exact retry returns its receipt; a changed retry conflicts.
- `log_go`: accepted game, saved roster player, round/go and ordered start/end timestamps. Calls the restricted six-argument helper. The unused broken ten-argument overload is dropped.
- `append_event`: `{match_id, game_id, event:{player_id, round_index, dart_index}}`. Event identity/kind/points derive from the accepted board. No arbitrary client event payload is stored.
- `resume`, `renew`, `list_roster`, `revoke_controller`, `cleanup_game`, `cleanup_match` operate only on the live controller scope. Cleanup cannot remove accepted games. Renew extends the same secret by 24 hours; expired/revoked credentials cannot renew or adopt historical IDs.

Training API is separate from competitive matches: `create_training` takes `{player, mode, length, config}` and returns training_id/expiry/capability. Modes standard/tdb/select and lengths 0/10/15 match current source. `complete_training` takes `{training_id,payload}` with the existing training columns; completed and partial-go results contain their actual 1–3 darts, with exact aggregate validation. `resume_training` and `renew_training` require the same training capability.

`create_player` is INSERT-only and idempotent by exact request UUID/body. It never overwrites a same-name existing profile. `visit` accepts a UUID device_id, derives the current UTC server day, and inserts once per day/device. Global profile, history, repair, archive and destructive routes delegate to authenticated `admin_action` implemented in admin-command.sql.

Commentary verifies controller/game or live admin/session authority in its first service request. A private actor-bound claim permits one generation per game/kind. Commit rechecks actor authority after the asynchronous model call, so revocation/archive while generating denies the write. Production retains the deployed model/prompt contract. `tools/sc004-security/commentary-fixture.ts` is a separate local-only endpoint: real Auth/Edge/SQL/service behavior, deterministic upstream model output, no paid model request or production bypass. The legacy PIN Edge endpoint returns 410.

Deploy the compatible package in two bounded phases:

1. Fresh original catalog preflight, then gameplay.sql, lifecycle.sql, admin-command.sql and commentary-authority.sql. The private hold starts enabled. Root allocates the actual migration with `supabase migration new`.
2. Deploy the secure app/Edge paths, establish a real owner-controlled admin, release the hold through trusted `sq_sc004_set_hold(false)`, and prove admin/capability routes alongside the old path where safe.
3. Drain pre-cutover browser sessions and finish/recover all legacy in-flight games before narrowing authority. Old client-generated IDs have no registry. The secure app requires a new issued controller; cached old clients fail closed after closure and must refresh. Do not adopt an old match by public ID/name or claim drain from an absence of public unfinished games. The explicit `admin_action/recover_legacy` route verifies the real owner admin and derives the controller from locked existing database match truth; its fourth SQL argument is the server-issued hash. Recovery retains accepted history and grants the restored cached current game a pending slot. Ordinary callers cannot invoke this owner recovery.
4. Immediately rerun closure-preflight.sql: original catalog objects plus the exact new function manifest. Then apply closure.sql and rerun full platform/browser acceptance. Read-only views and publications retain their existing behavior; mutation closure is exactly 18 base tables, the writable v_games_visible, four sequences and privileged RPCs.

Local reconstruction may produce documented PostgreSQL deparser aliases without changing logical view output. The isolated rehearsal uses its separately frozen local catalog hashes; the production guard keeps the original production hashes. Neither guard silently accepts drift.

Restricted rollback: execute `tools/sc004-security/restricted-recovery.sql`, retain all controllers, slots, training scopes, queues and accepted receipts, and serve the last verified compatible secure app/Edge anchor. `function-recovery.sql` restores only the reviewed secure functions while holding writes. It does not restore anonymous policies/grants or the retired PIN/commentary bypasses. A trusted hold pauses lifetime for credentials valid when held; expired-before-hold and revoked credentials remain denied. Verify real Auth/Edge/PostgREST/Realtime behavior before releasing that hold. Any memory-only cache requires an explicit tab-loss warning; there is no public-ID credential recovery.
